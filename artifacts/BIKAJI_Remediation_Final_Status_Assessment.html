D6 — Terminal UPSERT Protection: Right Direction, Test Is Insufficient

The conditional update clause added to PostgreSQL:

ON CONFLICT (symbol, breakout_type, scanner, alert_date)
DO UPDATE
SET ...
WHERE alerts.status IN ('OPEN', 'ACTIVE')
RETURNING id, (xmax = 0) AS is_insert

When an existing row is terminal (WIN, LOSS, CLOSED), the WHERE condition evaluates to false, causing PostgreSQL to return no row (fetchone() is None).

Required Behavioral Checks:

  • A WIN, LOSS, or CLOSED conflict remains terminal.
  • Existing exit price, P&L, exit reason, and lifecycle fields remain unmodified.
  • The no-row result (None) is safely handled by application code.
  • Repeated scans cannot generate another eligible BUY through a caller-side fallback.

Assessment: PROMISING SQL CLAUSE — NOT BEHAVIORALLY CERTIFIED.
