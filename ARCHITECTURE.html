ELITE BREAKOUT SYSTEM: V8 ARCHITECTURE MANUAL

Last Updated: 2026-07-21 | System Version: V8.0 / Target Engine v7.1

1. Executive Overview

The Elite Breakout System is a fully automated, cloud-native trading scanner and signal engine designed exclusively for the Indian Equity Market (NSE/BSE). The core objective is to identify, score, rank, and track high-probability momentum, breakout, and reversal setups with institutional conviction.

1.1 Purpose & Boundaries

  • Fully Automated Scanning: Runs 24/7 on Railway, managing intra-day loops, end-of-day filters, and fundamental sector rotation algorithms.
  • Signal Generation (Not Execution): The system generates actionable signals (Entry, Target, Stop Loss), orchestrates risk management via a dynamic partial exit architecture, and sends notifications (Telegram/Email/Push). It does not execute trades via broker APIs.
  • Zero Assumptions: Every decision must be mathematically proven by technical/fundamental indicators, validated by data, and corroborated by volume and market regime.

1.2 Core Subsystems

  • Scanner Framework: eod_scanner.py, reversal_scanner.py, multi_tf_scanner.py, multibagger.py, wealth_engine.py
  • Data Layer: Factory pattern data_provider.py (Fyers -> YFinance -> BSE mapping), price_cache.py (Parquet), delivery_data.py.
  • Decision Engine: scoring_engine.py (Quality, Technical, Regime, Bayesian Weights) and trade_ranking_engine.py.
  • Risk Management: sl_target_helper.py (ATR, S/R Cluster mapping), performance_tracker.py (tick-by-tick partial exit tracking).
  • Orchestrator: main.py (Watchdog, Scheduler), memory_profiler.py (Memory GC, malloc_trim, Subsystem Attribution).
  • AI / Fundamental: ai_worker.py, pledge_worker.py, daily_builder.py.
  • Presentation: Flask dashboard (dashboard_server.py).

4. Complete Startup Flow

The startup lifecycle in main.py guarantees that the environment is strictly validated before any heavy processing begins.

  1. Timezone Fix: Injects `ist_converter` into standard python `logging` to ensure all logs use IST (Asia/Kolkata).
  2. Diagnostics: Attempts to run `diagnostics.run_startup_diagnostics()`. Aborts boot via `sys.exit(1)` if memory/disk checks fail.
  3. Database Cleanup: `_cleanup_old_scanner_names()` executes via Postgres cursor to delete stale thread names and reset 'DOWN' statuses to 'IDLE'.
  4. Watchlist Pre-flight: `_build_watchlist_background()` fires in a daemon thread. If `elite_watchlist.parquet` is missing, it calls `watchlist_cache.get_watchlist()` which relies on `daily_builder.py`.
  5. Thread Initializations:
    • MultiTFScanner via `run_multi_tf_scanner`
    • PerformanceTracker via `run_performance_tracker` (Forces a synchronous initial build, then loops every 5 min).
    • SystemScheduler via `run_system_scheduler` (The core cron loop managing 1AM, 2AM, 8:30AM, and market-hours).
    • EveningScanners via `run_evening_scanners` (EOD & Reversal).
    • MultibaggerScanner via `run_multibagger_scanner` (Runs daily at 19:00 IST).
    • AI Worker via `run_worker_loop` (Sleeps on weekends, loops every 3h).
  6. Flask Binding: The main thread invokes `app.run` (or Railway binds via gunicorn) connecting `dashboard_server.py` to `0.0.0.0`.
