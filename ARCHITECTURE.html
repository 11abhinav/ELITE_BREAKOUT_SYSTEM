3. Phase 3 — Component Architecture Specifications

1. Watchlist Daily Builder (app/daily_builder.py)

Purpose: Fetches fundamental data from TradingView screener API across 2,600+ NSE stocks, applies financial quality filters, calculates category classifications, and generates the master watchlist parquet file at /app/data/elite_fundamental_watchlist.parquet.

Hard Exclusions (Junk-Kill Gates):

  • MIN_PRICE = 100: Minimum CMP ₹100 to exclude penny stocks.
  • MIN_MARKET_CAP = 10,000,000,000: Minimum market cap ₹1,000 Cr.
  • MIN_ROE = 8%: Excludes insolvent businesses.
  • MAX_DEBT_EQUITY = 1.0: D/E > 1.0 blocked (exempt: Utilities / Banks / NBFCs).
  • MIN_PROMOTER_MCAP = 500 Cr: Blocks shell companies with inflated ROE.
  • MIN_OPM_NONFIN = 10%: Excludes commodity margins (non-financial).
  • MIN_ROA_FIN = 0.8%: Minimum ROA for banks/NBFCs.
  • ASM/GSM Guard: Blocks all 280 stocks present in live NSE surveillance list or promoter blacklist.

2. EOD Breakout Scanner (app/eod_scanner.py)

Purpose: Runs at 21:00 IST on the full watchlist. Computes 1-year daily indicators, evaluates breakout patterns, calculates 100-point scoring, and determines V7 dynamic Stop-Loss and Target levels.

Filter Cascade Sequence:

  1. Load Watchlist & Query PostgreSQL Promoter Pledge Map.
  2. Fetch NSE Bhavcopy delivery data (or fallback up to 5 days).
  3. Download 60-day OHLCV for 16 Sector Indices via sector_rotation.py.
  4. Download 5-day 15m intraday Nifty bars via macro_utils.py to classify market regime (BULLISH, NEUTRAL, BEARISH).
  5. Process 305 stocks in 7 chunks of 50 via fetch_watchlist_data().
  6. Calculate EMA20, EMA50, SMA50, SMA200, MACD, RSI, ADX, ATR, 52W Highs.
  7. Apply score threshold: 82 points (Neutral) / 87 points (Bearish).
  8. Execute V7 Dynamic SL/Target Engine.
  9. Persist qualified breakouts to PostgreSQL alerts table.

3. Pullback Continuation Scanner (app/pullback_pipeline.py)

Purpose: Runs after Reversal Scanner in the evening batch. Identifies high-probability pullback continuation patterns following an impulse move.

Filter Cascade Sequence:

  1. Hook into today's processed EOD price cache.
  2. Detect confirmed pivots using lookback=10, confirm=3.
  3. Identify valid impulse leg ($\ge 8.0\%$ gain, $\ge 3.0\times\text{ATR}$).
  4. Measure pullback structure (depth 5.0%–15.0%, duration 3–20 bars, volume ratio $\le 0.75$).
  5. Detect resumption trigger bar ($\ge 1.3\times$ median pullback volume, close in upper 60% of range).
  6. Calculate evidence bonus: +3 for prior EOD alert (last 30d), +2 for prior Multibagger/Multi-TF alert (capped at max bonus = 5).
  7. Persist candidates to PostgreSQL alerts table with scanner = 'PULLBACK'.

4. Phase 4 — Business Rule Extraction & Formulations

V7 Dynamic Stop-Loss & Target Engine (app/sl_target_helper.py)

Stop-Loss (SL) and Target calculations are calculated dynamically based on ATR and swing structure:

# 1. Primary Structural SL
structural_sl = Swing_Low_Lookback_10 - (0.5 * ATR_14)

# 2. Dynamic ATR SL Fallback
atr_sl = Close_Price - (2.0 * ATR_14)

# Selected SL = max(structural_sl, atr_sl) capped at max risk 8%
final_sl = max(structural_sl, atr_sl)
if (Close_Price - final_sl) / Close_Price > 0.08:
    final_sl = Close_Price * 0.92  # 8% Hard SL Cap

# Target 1 (T1) & Target 2 (T2) Calculations
Risk_Amount = Close_Price - final_sl
T1_Price = Close_Price + (1.5 * Risk_Amount)  # 1.5 R:R
T2_Price = Close_Price + (3.0 * Risk_Amount)  # 3.0 R:R

# Minimum Risk/Reward Filter Gate:
Risk_Reward_Ratio = (T1_Price - Close_Price) / Risk_Amount
if Risk_Reward_Ratio < 1.5:
    REJECT_CANDIDATE("REJ_LOW_RR")

11. Phase 11 — Memory Lifecycle & Native Arena Management

To prevent Linux container Out-Of-Memory (OOM Code 137) crashes, the system executes run_purge_with_telemetry() post-evening batch and pre-Daily Builder. This sequence purges price caches, runs gc.collect(), and triggers malloc_trim(0) via ctypes.CDLL("libc.so.6") to release glibc arena fragmentation back to the OS kernel.

12. Phase 12 — Multi-Threading Model & Synchronization Locks

  • AI Worker Thread: Daemon thread running run_worker_loop() in app/ai_worker.py.
  • Pledge Worker Thread: Daemon thread running worker_loop() in app/pledge_worker.py.
  • Self-Healing Watchdog: Background monitor checking thread health every 60 seconds in app/main.py.
  • _scan_lock: Reentrant lock preventing concurrent scanner runs.

13. Phase 13 — Error Handling, Retries & Fallbacks

The system enforces robust multi-tier fallback mechanisms:

  • Fyers API Fallback: If Fyers batch quotes fail or return incomplete bars, the system automatically falls back to YFinance API batch downloads.
  • Bhavcopy Fallback: If today's NSE delivery Bhavcopy is unreleased by 21:00 IST, EOD falls back to N-1 day Bhavcopy and issues an in-app warning notification.

14. Phase 14 — Data Validation & Quality Framework

Managed by DataQualityValidator (V8.0) in app/data_quality.py:

  • REJ_PRICE_NAN: Rejects DataFrames containing NaNs in High/Low/Close columns.
  • REJ_INSUFFICIENT_HISTORY: Rejects symbols with < 260 daily bars.
  • REJ_UNADJUSTED_DATA: Rejects data with unadjusted split/bonus jumps > 50%.

  5. Purge & Destruction: Dictionary cleared via clear_price_cache(), PyObject references destroyed via gc.collect(), and underlying native memory released back to Linux kernel via malloc_trim(0).
