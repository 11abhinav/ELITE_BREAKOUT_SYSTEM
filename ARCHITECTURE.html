This table documents every external network integration, endpoint, protocol, payload schema, and failure strategy:

Integration / API Protocol & Target Request Payload / Params Retry Policy & Timeout Fallback Mechanism Caching Strategy
Fyers API v2/v3 HTTPS REST (api.fyers.in) Batch Quotes: 50 symbols/chunk. Historical OHLCV: 1d, 15m. 3 Retries, exponential backoff (1s, 2s, 4s). Timeout: 10s. Falls back to YFinance API batch fetch. Cached in price_cache._cache & disk Parquet.
TradingView Screener HTTPS JSON POST (scanner.tradingview.com/india/scan) 27 fundamental fields (Market Cap, ROE, Debt/Equity, YoY Sales/Profit). 2 Retries. Timeout: 15s. Marks tradingview service failure in DB. Written to elite_fundamental_watchlist.parquet.
YFinance API HTTPS REST (query2.finance.yahoo.com) Ticker format: SYMBOL.NS. Historical 1d bars. 3 Retries per symbol. Timeout: 5s. Log warning, skip symbol if unavailable. Cached in price_cache._cache.
ScraperAPI Trendlyne HTTPS Proxy (api.scraperapi.com) Promoter Pledge percentage and NSE ASM/GSM status. 5 Retries with rotating residential proxies. Timeout: 20s. Retains previous promoter_pledge_cache row. PostgreSQL promoter_pledge_cache table.
Gemini 1.5 Flash AI API HTTPS REST (generativelanguage.googleapis.com) Concall transcript text prompt for sentiment extraction. 3 Retries. Rate limit: 15 RPM. Timeout: 30s. Returns null sentiment summary; candidate proceeds. PostgreSQL ai_concall_cache_v3 table.
PostgreSQL Database TCP SQL Connection (psycopg2 Pool) Min pool=2, Max pool=30. SSL mode required on Railway. Auto-reconnect on connection reset. Timeout: 10s. In-memory fallback queue for alerts. Database tables (alerts, scanner_health).

23. Phase 23 — Complete Object Lifecycle Documentation

PullbackCandidate Object Lifecycle

  1. Creation: Instantiated as dataclass in app/pullback_pipeline.py:85 with state = CandidateState.PENDING.
  2. Modification: Populated with PullbackStructure, TriggerSignal, entry_price, stop_loss, target_price, and score.
  3. Validation: State transitions to CandidateState.QUALIFIED if all filter gates pass; otherwise CandidateState.REJECTED with RejectionReason.
  4. Persistence: Serialized into dict and saved to PostgreSQL alerts table via save_alert_if_new().
  5. Release & GC: Reference dropped at end of scanner iteration loop; collected during gc.collect() stage of run_purge_with_telemetry().
