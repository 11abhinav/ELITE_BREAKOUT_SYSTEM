## 1. Specification vs. Implementation

**Current Specification (Constitution):**
"Once Target 1 is hit, stop-loss trails at 3 ATR below recent swing low."

**Current Implementation (`app/performance_tracker.py`):**
The code trails the stop-loss to Breakeven (`entry_price`) once Target 1 is hit.
```python
# app/performance_tracker.py
new_sl = t["entry_price"] if new_rem > 0 else sl  # Raise to Breakeven only if remaining shares exist
```

## 2. Evidence & Findings

- **Code Location:** `app/performance_tracker.py:367`
- **Historical Context:** This behavior was introduced as part of a "V2 Multi-Stage Target & Trail Processing" update. The commit history indicates a deliberate shift towards a multi-target scaling out model (T1, T2, T3) where T1 triggers a breakeven trail, rather than an ATR trailing logic.
- **Operational Impact:** Moving to breakeven is a tighter, risk-off mechanism compared to 3 ATR below a swing low. Breakeven protects capital faster but may result in being stopped out of runners prematurely compared to the ATR method.

## 3. Governance Assessment

**Classification:** Specification/Implementation Drift

**Questions for Review:**
1. Was the breakeven trail at T1 an intentional production decision to lock in risk?
2. If yes, should the Constitution be amended (Level 4 Change) to reflect Breakeven trailing?
3. If no, should the codebase be modified (Level 3 Change) to reinstate the 3 ATR trailing logic?
